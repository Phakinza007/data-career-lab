### ตัวรันโค้ด

**`<PyRunner>` — Python**
- Pyodide ทำงานใน Web Worker เพื่อไม่ให้หน้าเว็บค้าง
- โหลด runtime เมื่อกด Run ครั้งแรกเท่านั้น และใช้ worker ตัวเดียวร่วมกันทั้งหน้า
- แพ็กเกจ: pandas, numpy, matplotlib (ผลเป็น PNG), seaborn; scikit-learn เตรียมไว้สำหรับรอบ ML
- รองรับ state ต่อเนื่องภายในบท (เซลล์ถัดไปเห็นตัวแปรจากเซลล์ก่อน) แต่แบบฝึกแต่ละข้อรันใน namespace สะอาดของตัวเอง

**`<SqlRunner>` — SQL**
- DuckDB-wasm ใน Web Worker อ่าน CSV/parquet ได้ตรง
- ตาราง dataset ถูกลงทะเบียนไว้ให้ query ได้ทันที

**ร่วมกัน**
- ปุ่ม Run / Reset
- timeout 10 วินาที → terminate worker แล้วสร้างใหม่ แจ้งผู้ใช้ว่าถูกหยุดเพราะนานเกิน
- ผลลัพธ์ตาราง/DataFrame แสดง 20 แถวแรกพร้อมบอกจำนวนแถวทั้งหมด ข้อความ output ยาวเกินถูกตัด

### Dataset

- ไฟล์ CSV/parquet เล็ก (≤ 5MB ต่อไฟล์) ใน `public/data/` ใช้ร่วมทั้ง Python และ SQL
- Notebook `.ipynb` อยู่ใน `notebooks/` — มีปุ่มดาวน์โหลด และปุ่ม Open in Colab เมื่อ repo เป็น public

## 4. รูปแบบบทเรียนและแบบฝึก

ออกแบบตามลำดับที่แนะนำกันทั่วไปในการสอนทักษะ: ดูตัวอย่าง → เติมช่องว่าง → ทำเอง → ฝึกคละหัวข้อ → ทบทวนแบบเว้นระยะ

### โครงของทุกบท

1. **เป้าหมายของบท** — 2–3 bullet ว่าจบบทแล้วทำอะไรได้
2. **เนื้อหา** — ท่อนสั้นๆ แต่ละท่อนมีตัวอย่างโค้ดที่รันได้
3. **ลองเล่น** — runner ใส่โค้ดไว้ให้ แก้เล่นได้อิสระ ไม่ถูกตรวจ
4. **ตัวอย่างแก้โจทย์ (worked examples)** — 2–3 ตัวอย่าง
5. **เติมช่องว่าง (faded examples)** — 1–2 ข้อ
6. **แบบฝึกท้ายบท** — 8–12 ข้อ 3 ระดับ
7. **Quiz** — 3–5 ข้อปรนัย
8. **สรุปและคำถามสัมภาษณ์** — 1–3 ข้อ

### ตัวอย่างแก้โจทย์ `<WorkedExample>`

- แสดงโจทย์ แล้วเปิดวิธีคิดทีละขั้นด้วยปุ่ม "ขั้นต่อไป"
- ทุกขั้นมีโค้ดที่รันได้และคำอธิบายว่าทำไมทำแบบนี้
- มีส่วน "ทางที่คนมักพลาด" เช่น JOIN แล้วแถวเบิ้ล, GROUP BY ลืมคอลัมน์
- เรียงจากง่ายไปยาก ตัวสุดท้ายยากใกล้แบบฝึกระดับประยุกต์

### เติมช่องว่าง

- โค้ดจากตัวอย่างที่เว้นส่วนสำคัญไว้ (แสดงเป็น `___`) ให้ผู้เรียนเติมแล้วรันตรวจ
- ใช้กลไกตรวจเดียวกับแบบฝึก

### แบบฝึกท้ายบท

| ระดับ | จำนวน | ลักษณะ |
|---|---|---|
| 🟢 พื้นฐาน | 4–5 | ใช้สิ่งที่เพิ่งเรียนตรงๆ |
| 🟡 ประยุกต์ | 3–4 | ต้องรวมกับบทก่อนหน้า |
| 🔴 ท้าทาย | 1–3 | ระดับโจทย์สัมภาษณ์ |

### ชุดฝึกท้าย module

- หน้าแยก 15–20 ข้อคละหัวข้อทั้ง module ไม่บอกว่าข้อไหนใช้เทคนิคอะไร
- ใช้กลไกตรวจเดียวกับแบบฝึกท้ายบท

### หน้า Drill `/practice`

- สุ่มโจทย์จากบทที่เรียนผ่านแล้ว กรองตามหัวข้อ/ระดับได้
- ให้น้ำหนักข้อที่เคย "ผ่านด้วยเฉลย" หรือเคยตอบผิดมากกว่าข้ออื่น

### การตรวจแบบฝึก SQL

- แต่ละข้อเก็บ query เฉลยไว้ ระบบรันคำตอบผู้ใช้และเฉลยบน DuckDB ตัวเดียวกันแล้วเทียบผล
- ค่าตั้งต้นไม่สนลำดับแถว; ข้อที่ตั้ง `ordered` จะตรวจลำดับด้วย
- ไม่สนชื่อคอลัมน์ แต่จำนวนและลำดับคอลัมน์ต้องตรง
- ค่าทศนิยมยอมคลาดได้ 1e-6; NULL เทียบเท่ากับ NULL
- ผิดแล้วบอกจุดที่ผิด เช่น "ได้ 15 แถว ควรได้ 12" หรือแสดงแถวแรกที่ไม่ตรง

### การตรวจแบบฝึก Python

- แต่ละข้อมีโค้ดตรวจ (Python) รันต่อจากโค้ดผู้ใช้ใน namespace เดียวกัน
- โค้ดตรวจเรียก helper ที่เตรียมไว้ เช่น `check_df(result, expected, ordered=False)`, `check_value(x, 42)`
- helper แปลง error เป็นข้อความภาษาไทยที่อ่านเข้าใจ ไม่แสดง traceback ของตัวตรวจ

### ตัวช่วยและการนับความคืบหน้า

- hint หลายระดับ เปิดทีละขั้น
- ปุ่ม "ดูเฉลย" — ข้อที่ดูเฉลยบันทึกเป็น **ผ่านด้วยเฉลย** แยกจาก **ผ่านเอง**
- บท "เสร็จ" เมื่อผ่านแบบฝึกระดับพื้นฐานและประยุกต์ครบ; ระดับท้าทายเป็นดาวโบนัส; quiz เก็บคะแนนแต่ไม่บังคับ
- โค้ดที่พิมพ์ค้างในแต่ละข้อบันทึกอัตโนมัติ

### Flashcards

- ศัพท์สำคัญและคำถามสัมภาษณ์ของแต่ละบทรวมไว้ในหน้า `/review`
- ระบบ Leitner 5 กล่อง: ตอบถูกเลื่อนขึ้นกล่อง ตอบผิดกลับกล่อง 1

## 6. การจัดการ error

| สถานการณ์ | พฤติกรรม |
|---|---|
| โหลด Pyodide/DuckDB ไม่สำเร็จ | runner แสดงข้อความ + ปุ่มลองใหม่; เนื้อหาบทอ่านได้ตามปกติ |
| โค้ดวนไม่จบ | timeout 10 วินาที → terminate + สร้าง worker ใหม่ + แจ้งผู้ใช้ |
| โค้ดผู้ใช้ error (Python) | traceback ตัดเหลือเฉพาะบรรทัดของโค้ดผู้ใช้ |
| โค้ดผู้ใช้ error (SQL) | แสดงข้อความ error ของ DuckDB ตามจริง |
| ผลลัพธ์ใหญ่ | ตัดเหลือ 20 แถว + บอกจำนวนทั้งหมด; ข้อความยาวถูกตัด |
| localStorage ใช้ไม่ได้/ข้อมูลเสีย | อ่านเขียนครอบ try/catch; ถ้าพังใช้หน่วยความจำชั่วคราว + แถบเตือน; migrate ตาม schema version |

## 7. การทดสอบ

- **Unit (Vitest):** progress store, ตัวเทียบผล SQL, logic ของ Leitner, การเลือกโจทย์ของ Drill, schema frontmatter
- **Content test (สำคัญที่สุด):** รันแบบฝึก เติมช่องว่าง และชุดฝึกท้าย module ทุกข้อใน Node ด้วย DuckDB และ Pyodide ตัวเดียวกับบนเว็บ
  - เฉลยต้องผ่านตัวตรวจ
  - โค้ดเริ่มต้นต้องไม่ผ่าน
  - โค้ดใน worked example ทุกขั้นต้องรันได้ไม่ error
- **Dataset test:** ตรวจว่า pattern ที่ฝังยังอยู่ (ผล A/B มีนัยสำคัญ, cohort ที่กำหนด retention ตก, มีข้อมูลสกปรกครบตามที่บท cleaning ใช้)
- **E2E smoke (Playwright):** เปิดบท → รันโค้ด → ผ่านแบบฝึก → ความคืบหน้าอัปเดต
- **Build:** frontmatter ผิด schema → build ไม่ผ่าน
