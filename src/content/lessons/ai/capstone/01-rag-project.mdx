## โจทย์

สร้าง **ผู้ช่วยตอบคำถามลูกค้าจากฐานความรู้ร้านค้า** (`kb_docs.csv` 24 เอกสาร + ชุดคำถามมีเฉลย `kb_questions.csv` 30 ข้อ) ที่:

1. ค้นหาเอกสารที่เกี่ยวข้อง (retrieval)
2. ประกอบ prompt ที่ยึดบริบท อ้างอิง doc id และตอบ "ไม่รู้" เมื่อไม่มีข้อมูล
3. เรียกโมเดลสร้างคำตอบ (ใน notebook ต่อ API จริงได้ หรือใช้ตัวสำรองแบบไม่ต้องมี API key)
4. ตรวจผลลัพธ์ (การอ้างอิง) และ fallback
5. **ประเมินผลด้วยตัวเลข** ทั้ง retrieval และคำตอบ พร้อมวิเคราะห์จุดที่พลาด

## เตรียมตัว

ดาวน์โหลด notebook เริ่มต้นด้วยปุ่มด้านบน มีเซลล์ที่รันได้ทั้งหมดแบบ **ออฟไลน์** (retrieval ด้วย TF-IDF, ตัวสร้างคำตอบสำรองแบบสกัดประโยค) และเซลล์ที่ต่อ API จริงเมื่อคุณตั้งค่า `ANTHROPIC_API_KEY`
เก็บ API key ไว้ในตัวแปรสภาพแวดล้อมหรือ Colab Secrets เท่านั้น **ห้ามพิมพ์ลงใน notebook หรือ commit ขึ้น GitHub**

## ตัวเลขอ้างอิงจากบทเรียน (TF-IDF + stop words บน 30 คำถาม)

- retrieval: hit@1 0.6333, hit@3 0.8333, MRR 0.752 — จุดอ่อนอยู่ที่หมวด returns และคำถามที่ใช้คำต่างจากเอกสาร (paraphrase)
- ตัวสำรองแบบสกัดประโยค: ประโยคที่เลือกมาจากเอกสารเฉลย 19 จาก 30 ข้อ (0.6333)
- ตัวเลขเหล่านี้คือ **baseline ที่ต้องเอาชนะ** — โมเดลจริงและ retrieval ที่ดีขึ้น (embeddings, hybrid, query expansion) ควรทำได้ดีกว่า แต่ต้องวัดเอง ไม่ต้องเชื่อว่าจะดีกว่า และอย่าจูนกับ 30 ข้อเดียวจนแนบชุดนั้น (เขียนชุดคำถามใหม่อีกอย่างน้อย 10 ข้อไว้ตรวจสุดท้าย)

## Rubric ตรวจงานตัวเอง

- [ ] มี baseline และตัวเลข retrieval (hit@k, MRR) พร้อมวิเคราะห์หมวดที่พลาด
- [ ] prompt สั่งให้ยึดบริบท อ้างอิง doc id และปฏิเสธเมื่อไม่มีข้อมูล
- [ ] มีการตรวจฝั่งโค้ด: id ที่อ้างต้องอยู่ในชุดที่ดึงมา, มี fallback เมื่อไม่ผ่าน
- [ ] มีชุดคำถามนอกขอบเขตและวัดว่าระบบปฏิเสธถูกกี่ข้อ
- [ ] ประมาณต้นทุนต่อคำถามและต่อเดือน (บอกว่าใช้ราคาสมมติหรือราคาจริงจากผู้ให้บริการ)
- [ ] ไม่มี API key/ข้อมูลส่วนบุคคลใน repo
- [ ] notebook รันได้ทั้งไฟล์จากบนลงล่าง (อย่างน้อยเส้นทางออฟไลน์) โดยไม่ error
- [ ] มีหัวข้อ "ข้อจำกัด" และ "ทำอะไรต่อ" ที่ซื่อตรง

## ต่อยอด (ถ้ามีเวลา)

- ใช้ embedding model จริงแทน TF-IDF แล้วเทียบด้วยชุดคำถามเดิม
- เพิ่มเครื่องมือ (เช่น ดูสถานะออเดอร์จากตาราง orders) ให้กลายเป็น agent ที่ตอบได้ทั้ง "นโยบาย" และ "ข้อมูลลูกค้า" พร้อมกันสิทธิ์ตาม module agents
- ทำหน้าเว็บ/CLI เล็กๆ และบันทึก log คำถาม-คำตอบ-ต้นทุน
