## จากผลค้นหา → prompt ที่ตอบได้และตรวจสอบได้

หลังได้ top-k เอกสารแล้ว ขั้นต่อไปคือประกอบ prompt ที่สั่งให้โมเดล **ตอบจากบริบทที่ให้เท่านั้น อ้างอิง doc id และยอมบอกว่า "ไม่รู้"** — สามข้อนี้คือหัวใจที่ทำให้ RAG น่าเชื่อถือกว่าให้โมเดลตอบจากความจำ

```python
TEMPLATE_RAG = (
    "Answer the question using ONLY the context below. Cite the doc ids in square brackets. "
    "If the answer is not in the context, reply exactly: I don't know.\n\n"
    "Context:\n{context}\n\nQuestion: {question}\nAnswer:"
)

hits = retrieve(question, k=3)                       # [(doc_id, score), ...]
context = "\n".join(f"[{d}] {title}: {text}" for d, title, text in rows)
prompt = TEMPLATE_RAG.format(context=context, question=question)
```

โค้ดจริงส่ง `prompt` เข้า API (`client.messages.create(..., messages=[{"role": "user", "content": prompt}])`)
**ในบทนี้ไม่ได้เรียกโมเดลจริง** — เราใช้ `mock_answer` ที่ *สกัดประโยค* จากเอกสารที่ดึงมา (เลือกประโยคที่มีคำสำคัญร่วมกับคำถามมากสุด) เป็นตัวแทน เพื่อให้วัดและทดสอบ pipeline ได้ซ้ำทุกครั้ง มันไม่ฉลาดเท่า LLM แต่ทำให้เห็นว่าคุณภาพขึ้นกับสิ่งที่ retrieval ส่งมา

## เมื่อไม่มีคำตอบ: threshold ของคะแนน

ถ้าคำถามไม่เกี่ยวกับฐานความรู้ retrieval ก็ยังคืนอะไรบางอย่างเสมอ — ต้องมีเกณฑ์ตัดว่า "ไม่พบข้อมูล"
จากข้อมูลของเรา: คะแนนอันดับ 1 ของคำถามในขอบเขต 30 ข้อมี median 0.327 แต่ต่ำสุด 0.0 (คำถาม "Where is my package right now?" ไม่ตรงคำกับเอกสารใดเลย เพราะเอกสารใช้คำว่า parcel), คำถามนอกขอบเขต 6 ข้อ (เช่น "What is the capital of France?") ได้ 0.0 ทั้งหมดยกเว้น "Do you sell insurance?" ได้ 0.24 เพราะเอกสาร d20 มีคำว่า "sell"

| threshold | ตอบคำถามในขอบเขตได้ | ตอบคำถามนอกขอบเขต (ควรปฏิเสธ) |
|---|---|---|
| 0.05 – 0.15 | 29 / 30 | 1 / 6 |
| 0.20 | 26 / 30 | 1 / 6 |

การตั้ง threshold แลกกันระหว่างปฏิเสธคำถามที่ตอบได้ (recall ลด) กับยอมรับคำถามนอกเรื่อง — และเกณฑ์คะแนนตัวเดียวแยกไม่สะอาด (คำถามนอกเรื่องบังเอิญมีคำร่วมได้) ในงานจริงจึงเพิ่มการให้โมเดลปฏิเสธ (จากคำสั่งใน prompt) และตรวจอ้างอิง

## ตรวจว่าอ้างอิงจริง (faithfulness เบื้องต้น)

คำตอบที่อ้าง `[d01][d99]` ต้องอ้างเฉพาะ doc id ที่ **อยู่ในบริบทที่ส่งไป** จริง — id ที่ไม่มีอยู่คือสัญญาณว่าโมเดลแต่งขึ้น (hallucinate) ตรวจได้ด้วย regex `\[(d\d+)\]` แล้วเทียบกับชุดที่ดึงมา

## ความหลากหลายของบริบท: MMR

ถ้า top-k คล้ายกันเองหมด (ซ้ำซ้อน) จะเสียที่ context ไปเปล่าๆ **MMR** เลือกทีละอันด้วยคะแนน λ·(คล้ายคำถาม) − (1−λ)·(คล้ายอันที่เลือกแล้วมากสุด)
ในข้อมูลของเรา MMR (λ = 0.7, k = 3) ได้ hit@3 0.8 เทียบกับ top-3 ปกติ 0.8333 — ไม่ได้ช่วย เพราะเอกสารสั้นและไม่ซ้ำซ้อนกันอยู่แล้ว (ควรใช้เมื่อมีข้อมูลซ้ำมาก)

ผลของ `mock_answer` เมื่อได้ top-3: ประโยคที่เลือกมาจากเอกสารเฉลย 19 จาก 30 ข้อ (0.6333) — เท่ากับตอนได้แค่ top-1 ซึ่งบอกว่า **คอขวดอยู่ที่การเลือกประโยคและ retrieval อันดับ 1** ไม่ใช่จำนวนเอกสารที่ส่ง
