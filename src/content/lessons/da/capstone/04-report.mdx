## งานวิเคราะห์ที่ไม่มีใครอ่าน เท่ากับไม่ได้ทำ

ตัวเลขทั้งหมดพร้อมแล้วและตรวจสอบแล้ว เหลือขั้นสุดท้ายที่มักถูกให้เวลาน้อยที่สุดแต่ตัดสินผลมากที่สุด —
**การเรียบเรียงให้คนอ่านตัดสินใจได้**

กติกาข้อแรกคือ **เอาข้อสรุปขึ้นก่อน** ไม่ใช่เล่าตามลำดับที่เราทำงาน คนอ่านไม่ได้อยากรู้ว่าเราเขียน query
กี่รอบ เขาอยากรู้ว่า "แล้วไงต่อ" — ถ้าเขาอ่านแค่สามบรรทัดแรกแล้วหยุด เขาต้องได้ข้อสรุปที่สำคัญที่สุดไปแล้ว

## โครงรายงานที่ใช้ได้กับงานเกือบทุกชิ้น

| ส่วน | ความยาว | เนื้อหา |
| --- | --- | --- |
| 1. Executive summary | 3–5 บรรทัด | คำถาม ข้อสรุป และข้อเสนอ |
| 2. ตัวเลขหลัก | ตารางเดียว | ตัวชี้วัดสำคัญเทียบสองช่วงเวลา |
| 3. Insight | 3–5 ข้อ | แต่ละข้อมีตัวเลข จุดเทียบ และ "แล้วไง" |
| 4. ข้อเสนอ | 2–4 ข้อ | เรียงตามผลตอบแทนต่อแรงที่ใช้ |
| 5. ข้อจำกัดและขั้นต่อไป | สั้นๆ | อะไรที่ข้อมูลนี้ตอบไม่ได้ |
| 6. ภาคผนวก | เท่าที่จำเป็น | นิยาม วิธีคำนวณ โค้ด |

สังเกตว่ารายละเอียดวิธีทำอยู่ล่างสุด — ไม่ใช่เพราะไม่สำคัญ แต่เพราะคนที่อยากรู้จะเลื่อนลงไปอ่านเอง
ส่วนคนที่ต้องตัดสินใจจะอ่านแค่สองส่วนแรก

## Executive summary ของ capstone นี้

> **คำถาม:** รายได้ปี 2025 โต 21.3% — การเติบโตนี้ยั่งยืนแค่ไหน และควรลงแรงต่อที่ไหน
>
> **ข้อสรุป:** การเติบโตมาจากการหาลูกค้าใหม่เกือบทั้งหมด (84% ของรายได้ปี 2025) ขณะที่ลูกค้าปี 2024
> กลับมาซื้อเพียง 17.5% และ AOV แทบไม่ขยับ (+0.03%) — รูปแบบนี้ต้องเติมลูกค้าใหม่ตลอดเวลา
> เพื่อรักษายอด จึงยังไม่ถือว่ายั่งยืน
>
> **ข้อเสนอหลัก:** ปล่อยหน้า checkout เวอร์ชัน B ให้ผู้ใช้ทุกคน (พิสูจน์แล้วว่าดีกว่าจริง),
> ย้ายงบจากแคมเปญแบบ `promo` ไปยังช่องทางที่ได้ลูกค้าคุณภาพสูงกว่า และเริ่มทำแคมเปญดึงลูกค้ากลุ่ม
> at_risk กลับมา

## เขียน insight ให้ครบสี่ส่วน

ทบทวนจาก module visualization: insight ที่ใช้งานได้ต้องมี **สิ่งที่พบ + ตัวเลข + จุดเทียบ + แล้วไง**

| --- | --- |

| กลาง | "84% ของรายได้ปี 2025 มาจากลูกค้าที่เพิ่งซื้อครั้งแรกในปีนั้น" |
| ดี | "84% ของรายได้ปี 2025 มาจากลูกค้าที่เพิ่งซื้อครั้งแรกในปีนั้น ขณะที่ลูกค้าปี 2024 กลับมาซื้อเพียง 17.5% — แปลว่ารายได้ปีหน้าจะตกทันทีถ้าช่องทางหาลูกค้าใหม่สะดุด จึงควรเริ่มลงทุนกับการรักษาลูกค้าเดิมตั้งแต่ไตรมาสนี้" |

ประโยคระดับ "ดี" ยาวกว่าจริง แต่คนอ่านไม่ต้องถามอะไรต่อ และตัดสินใจได้เลย

## เลือกกราฟเท่าที่จำเป็น

รายงานนี้ต้องการกราฟแค่ 3 อัน — แต่ละอันตอบหนึ่งคำถามที่ตารางตอบได้ไม่ดีเท่า:

1. **กราฟเส้นรายได้รายเดือน 2024–2025** — ให้เห็นฤดูกาลและแนวโน้ม (ตารางตัวเลข 24 แถวอ่านยากกว่ามาก)
2. **กราฟแท่ง retention เดือนที่ 1 แยกช่องทาง** — ให้เห็นทันทีว่า `promo` ต่ำกว่าเพื่อนแค่ไหน
3. **กราฟ funnel** — ให้เห็นว่าคนหายไปตรงไหนมากที่สุด

กราฟที่ไม่ได้ตอบคำถามไหนโดยเฉพาะ (เช่น pie chart ของสัดส่วนเมือง) ทำให้รายงานยาวขึ้นโดยไม่ช่วยตัดสินใจ
— ตัดทิ้งได้เลย

ขั้นตอนการทำกราฟใน Python คือ **เตรียมข้อมูลให้พร้อมก่อน แล้วค่อยวาด** ซึ่งเป็นวิธีที่ตรวจสอบง่ายกว่ามาก
เพราะข้อมูลที่เตรียมไว้เช็คความถูกต้องได้ ส่วนภาพที่วาดออกมาเช็คไม่ได้:

```python
import pandas as pd
import matplotlib.pyplot as plt

orders = pd.read_csv("data/orders.csv", parse_dates=['order_date'])
items = pd.read_csv("data/order_items.csv")
items['line'] = items['quantity'] * items['unit_price']
sales = items.merge(orders, on='order_id')
sales = sales[sales['status'] == 'completed']
monthly = sales.groupby(sales['order_date'].dt.to_period('M').astype(str))['line'].sum()

plt.plot(monthly.index, monthly.values)
plt.title('รายได้รวมรายเดือน 2024–2025')
plt.xlabel('เดือน')
plt.ylabel('รายได้ (บาท)')
plt.xticks(rotation=90)
```

## ข้อเสนอต้องเรียงตามผลตอบแทนต่อแรงที่ใช้

| ข้อเสนอ | หลักฐาน | แรงที่ใช้ | ผลที่คาด |
| --- | --- | --- | --- |
| ปล่อย checkout เวอร์ชัน B ให้ทุกคน | A/B test: 8.76% เทียบ 7.15% (p < 0.001) | ต่ำ (โค้ดพร้อมแล้ว) | purchase rate +22% |
| แคมเปญดึงกลุ่ม at_risk | 383 คน เคยสร้างรายได้ 24.3% เฉลี่ย 20,608/คน | กลาง | รายได้จากลูกค้าเดิมเพิ่ม |
| ทบทวนแคมเปญแบบ promo | retention 7.3% เทียบค่าเฉลี่ย 22–29% | กลาง | ลดงบที่เสียเปล่า |
| แก้จุดรั่วขั้น add_to_cart | คนหายไป 65% ในขั้นเดียว | สูง (ต้องวิจัยผู้ใช้ก่อน) | ผลมากที่สุดถ้าสำเร็จ |

ข้อเสนอที่เขียนแบบนี้ทำให้ทีมเลือกได้เองว่าจะเริ่มจากอะไร และเห็นว่าแต่ละข้อมาจากหลักฐานอะไร

## จัดเป็น portfolio ที่คนอื่นเปิดดูได้

เมื่อจะเอาขึ้น GitHub ให้จัดโครงแบบนี้:

```
sales-growth-analysis/
├── README.md          ← รายงานฉบับย่อ + ภาพกราฟ + วิธีรัน
├── data/              ← ข้อมูล (หรือสคริปต์ที่สร้างข้อมูล)
├── notebooks/         ← การวิเคราะห์ทีละขั้น
├── sql/               ← query ที่ใช้จริง
└── charts/            ← ไฟล์ภาพที่ใช้ใน README
```

`README.md` คือสิ่งที่คนอ่านก่อนเสมอ (และบ่อยครั้งคืออ่านอย่างเดียว) จึงต้องมี: คำถาม ข้อมูลที่ใช้
วิธีวิเคราะห์โดยย่อ ข้อค้นพบหลักพร้อมกราฟ ข้อเสนอ ข้อจำกัด และวิธีรันโค้ดซ้ำ

สิ่งที่ทำให้ portfolio ของ DA ดูน่าเชื่อถือในสายตาคนสัมภาษณ์ ไม่ใช่จำนวนกราฟหรือความซับซ้อนของโมเดล
แต่คือ **การเห็นว่าผู้เขียนคิดยังไง** — ตั้งคำถามเป็น เลือกวิธีเป็น ตรวจงานตัวเองเป็น
และรู้ว่าข้อมูลตอบอะไรไม่ได้

## เล่าให้ฟังใน 2 นาที

ในห้องสัมภาษณ์มักได้เวลาสั้นมาก โครงที่ใช้ได้เสมอคือ:

1. **คำถามและทำไมมันสำคัญ** (20 วินาที)
2. **สิ่งที่ทำ** (30 วินาที) — แตกเป็นคำถามย่อย ใช้ cohort/funnel/กำไร ตรวจด้วย z-test
3. **สิ่งที่พบ พร้อมตัวเลข** (40 วินาที)
4. **ข้อเสนอและข้อจำกัด** (30 วินาที)

ถ้าเขาสนใจจะถามต่อเอง และคำถามที่เจอบ่อยที่สุดคือ "รู้ได้ยังไงว่าตัวเลขถูก" — ซึ่งบทที่แล้วเตรียมคำตอบไว้ให้แล้ว
