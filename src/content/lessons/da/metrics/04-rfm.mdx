## แบ่งลูกค้าด้วยพฤติกรรม ไม่ใช่ด้วยความรู้สึก

ทีมการตลาดมีงบจำกัด ส่งโปรโมชันหาลูกค้าทุกคนไม่ไหวและไม่คุ้ม คำถามคือ "ควรคุยกับใครก่อน"
วิธีแบ่งลูกค้าที่ง่ายที่สุดและใช้กันมานานคือ **RFM** ซึ่งดูพฤติกรรมการซื้อจริงเพียง 3 มิติ:

- **R — Recency**: ซื้อครั้งล่าสุดเมื่อไหร่ (ยิ่งใกล้ยิ่งดี)
- **F — Frequency**: ซื้อมาแล้วกี่ครั้ง (ยิ่งมากยิ่งดี)
- **M — Monetary**: จ่ายไปทั้งหมดเท่าไหร่ (ยิ่งมากยิ่งดี)

ข้อดีของ RFM คือใช้แค่ตารางออเดอร์ที่ทุกบริษัทมีอยู่แล้ว ไม่ต้องมีโมเดลอะไรซับซ้อน
และผลลัพธ์อธิบายให้คนนอกทีม data ฟังได้ในประโยคเดียว

บทนี้เขียนด้วย pandas เพราะขั้นตอนการให้คะแนนและแบ่งกลุ่มอ่านง่ายกว่าใน Python
(ท้ายบทมีแบบฝึกที่ทำแบบเดียวกันด้วย SQL ให้ลองด้วย)

## ขั้นที่ 1: สร้างตาราง RFM ระดับลูกค้า

ข้อมูลไม่มี "วันนี้" จริง จึงใช้วันที่ล่าสุดในระบบ (31 ธ.ค. 2025) เป็นจุดอ้างอิงของ recency

```python
import pandas as pd

orders = pd.read_csv("data/orders.csv", parse_dates=['order_date'])
items = pd.read_csv("data/order_items.csv")
items['line'] = items['quantity'] * items['unit_price']
sales = items.merge(orders, on='order_id')
sales = sales[sales['status'] == 'completed']

asof = pd.Timestamp('2025-12-31')
rfm = sales.groupby('customer_id').agg(
    recency=('order_date', lambda s: (asof - s.max()).days),
    frequency=('order_id', 'nunique'),
    monetary=('line', 'sum'),
)
```

ได้ลูกค้า 2,707 คนที่เคยซื้อจริง โดย recency อยู่ระหว่าง 0–728 วัน, frequency 1–12 ครั้ง
และ monetary 109–98,881 บาท

สังเกตว่า `frequency` ใช้ `'nunique'` กับ `order_id` ไม่ใช่ `'size'` — เพราะหลัง merge
หนึ่งแถวคือหนึ่งรายการสินค้า (กับดักเดิมจากบทที่ 1 ที่ตามมาหลอกอีกครั้ง)

## ขั้นที่ 2: ให้คะแนน 1–4 แต่ละมิติ

วิธีมาตรฐานคือแบ่งลูกค้าเป็น 4 กลุ่มเท่าๆ กัน (quartile) ด้วย `pd.qcut()` แล้วให้คะแนน 1–4

```python
rfm['R'] = pd.qcut(rfm['recency'], 4, labels=[4, 3, 2, 1]).astype(int)
```

**สังเกต labels ของ R ที่กลับหัว**: recency น้อย (เพิ่งซื้อ) ต้องได้คะแนนสูง จึงต้องเรียง label
จาก 4 ลงไป 1 — จุดนี้พลาดกันบ่อยมากและตรวจจับยาก เพราะโค้ดรันผ่านและได้ตัวเลขหน้าตาปกติทุกอย่าง

ส่วน `monetary` เป็นค่าต่อเนื่องเหมือนกัน ใช้ `qcut` ได้ตรงๆ:

```python
rfm['M'] = pd.qcut(rfm['monetary'], 4, labels=[1, 2, 3, 4]).astype(int)
```

## เมื่อ qcut ใช้ไม่ได้: ค่าซ้ำเยอะเกินไป

พอลองกับ `frequency` จะเจอ error ทันที:

```
ValueError: Bin edges must be unique: Index([1.0, 1.0, 2.0, 3.0, 12.0], ...)
```

เพราะลูกค้า 1,181 คนจาก 2,707 คน (43.6%) ซื้อแค่ครั้งเดียว — ขอบของ quartile ที่ 25% และ 50%
จึงตกที่ค่าเดียวกัน (1.0) ทั้งคู่ `qcut` แบ่งกลุ่มเท่าๆ กันไม่ได้เมื่อค่าซ้ำกันเยอะขนาดนี้

ทางแก้ที่ **ไม่ควร**ใช้คือ `rfm['frequency'].rank(method='first')` แล้วค่อย `qcut` — วิธีนี้แบ่งได้ 4 กลุ่ม
เท่าๆ กันจริง แต่ลูกค้าที่ซื้อ 1 ครั้งเหมือนกันเป๊ะจะถูกแยกไปคนละคะแนนตามลำดับแถวในตาราง
เวลาทีมการตลาดถามว่า "ทำไมลูกค้าคนนี้ได้คะแนนต่ำกว่าอีกคนทั้งที่ซื้อเท่ากัน" จะตอบไม่ได้เลย

ทางแก้ที่ดีกว่าคือ **กำหนดเกณฑ์เองตามความหมายทางธุรกิจ** ซึ่งอธิบายได้และคงที่ข้ามเดือน:

```python
def score_frequency(n):
    if n == 1:
        return 1
    if n == 2:
        return 2
    if n == 3:
        return 3
    return 4

rfm['F'] = rfm['frequency'].apply(score_frequency)
```

ได้จำนวนลูกค้าแต่ละคะแนน: 1 ครั้ง 1,181 คน, 2 ครั้ง 689 คน, 3 ครั้ง 342 คน, ตั้งแต่ 4 ครั้งขึ้นไป 495 คน
— กลุ่มไม่เท่ากันเป๊ะ แต่เกณฑ์ชัดเจนและอธิบายได้ ซึ่งสำคัญกว่าความเท่ากันของขนาดกลุ่ม

## ขั้นที่ 3: แปลงคะแนนเป็นกลุ่มที่ทำอะไรต่อได้

คะแนนรวม (`R + F + M`) ใช้จัดอันดับได้ แต่บอกไม่ได้ว่าควร**ทำอะไร** เพราะคะแนน 8 อาจมาจาก
R=4,F=2,M=2 (เพิ่งซื้อแต่ซื้อไม่บ่อย) หรือ R=1,F=4,M=3 (เคยเป็นลูกค้าชั้นดีแต่หายไปนานแล้ว) ซึ่งต้องทำคนละอย่างกันคนละขั้ว

กลุ่มที่ใช้งานได้จริงจึงมาจากการรวม R กับ F เข้าด้วยกันตามความหมาย:

```python
def segment(row):
    if row['R'] >= 4 and row['F'] >= 3:
        return 'champions'      # เพิ่งซื้อและซื้อบ่อย
    if row['R'] <= 2 and row['F'] >= 3:
        return 'at_risk'        # เคยซื้อบ่อย แต่หายไปนานแล้ว
    if row['R'] >= 3 and row['F'] == 1:
        return 'new_one_time'   # เพิ่งซื้อครั้งแรกครั้งเดียว
    if row['R'] == 1 and row['F'] <= 2:
        return 'lost'           # หายไปนานและแทบไม่เคยซื้อซ้ำ
    return 'others'

rfm['segment'] = rfm.apply(segment, axis=1)
```

ผลลัพธ์ของข้อมูลชุดนี้:

| segment | ลูกค้า | รายได้ | % ของรายได้ | เฉลี่ยต่อคน |
| --- | --- | --- | --- | --- |
| others | 875 | 10,422,373 | 32.0% | 11,911 |
| **at_risk** | **383** | **7,893,023** | **24.3%** | **20,608** |
| champions | 294 | 7,034,614 | 21.6% | 23,927 |
| lost | 545 | 4,038,093 | 12.4% | 7,409 |
| new_one_time | 610 | 3,143,875 | 9.7% | 5,154 |

## อ่านตารางนี้ให้เป็นข้อเสนอ

ตัวเลขที่สะดุดตาที่สุดคือ `at_risk`: ลูกค้าเพียง 383 คน (14% ของฐานลูกค้า) แต่เคยสร้างรายได้ถึง 24.3%
และเฉลี่ยต่อคน 20,608 บาท — สูงเป็นอันดับสองรองจาก champions เท่านั้น คนกลุ่มนี้เคยซื้อบ่อย
แต่หายไปนานแล้ว **ถ้าจะใช้งบแคมเปญดึงลูกค้ากลับ กลุ่มนี้คือกลุ่มที่คุ้มที่สุด** เพราะเขารู้จักร้านเราดีอยู่แล้ว
และเคยพิสูจน์มาแล้วว่ายอมจ่าย

ตรงข้ามกับ `new_one_time` (610 คน แต่ได้รายได้แค่ 9.7%) ที่ควรใช้วิธีถูกๆ อย่างอีเมลต้อนรับอัตโนมัติ
มากกว่าส่วนลดก้อนใหญ่ ส่วน champions ไม่ต้องให้ส่วนลดเลยด้วยซ้ำ — เขาซื้ออยู่แล้ว
ส่วนลดที่ให้ไปคือกำไรที่หายไปเปล่าๆ (เรียกว่า cannibalization)

## ข้อควรระวังของ RFM

1. **RFM เป็นภาพ ณ วันที่อ้างอิงเท่านั้น** ถ้าเปลี่ยน `asof` ทุกคะแนนเปลี่ยนหมด ต้องระบุวันที่อ้างอิงในรายงานเสมอ
2. **คะแนนเป็นอันดับ ไม่ใช่ปริมาณ** R=4 ไม่ได้แปลว่า "ดีเป็นสองเท่า" ของ R=2 มันแค่บอกว่าอยู่ควอไทล์ที่สูงกว่า
3. **ธุรกิจที่ลูกค้าซื้อนานๆ ครั้งโดยธรรมชาติ** (เช่น เฟอร์นิเจอร์ เครื่องใช้ไฟฟ้าชิ้นใหญ่) ต้องปรับกรอบเวลา
   ไม่งั้นลูกค้าปกติจะถูกจัดเป็น at_risk ทั้งหมด
4. **RFM บอกว่า "ใครน่าคุยด้วย" ไม่ได้บอกว่า "พูดอะไร"** ส่วนนั้นยังต้องใช้ความเข้าใจสินค้าและลูกค้าเหมือนเดิม
