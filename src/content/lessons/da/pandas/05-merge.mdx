## จาก JOIN สู่ merge

บทนี้คือ "SQL JOIN" เวอร์ชัน pandas — แนวคิดเหมือนกันทุกประการ (เทียบกับ `da/sql/03-joins` ได้เลย)
ต่างกันแค่ syntax:

```python
orders.merge(customers, on='customer_id')
```

## how='inner'/'left'/'right'/'outer'

| `how=` | เก็บแถวไหนไว้ |
| --- | --- |
| `'inner'` (ค่าเริ่มต้น) | เฉพาะแถวที่จับคู่ได้ทั้งสองฝั่ง |
| `'left'` | ทุกแถวจากตารางซ้าย ต่อให้หาคู่ในตารางขวาไม่เจอก็ใส่ NaN แทน |
| `'right'` | ทุกแถวจากตารางขวา (ตรงข้ามกับ left) |
| `'outer'` | ทุกแถวจากทั้งสองฝั่ง ไม่ว่าจะจับคู่ได้หรือไม่ |

ลองเชื่อม `customers` กับ `orders` ดู: `inner`/`right` ได้ 6,938 แถว (จำนวนออเดอร์) ส่วน `left`/`outer` ได้ 7,399 แถว
(เพิ่มมา 461 แถว คือลูกค้าที่ไม่เคยสั่งซื้อเลย) — ผลเดียวกับที่เจอตอนเรียน SQL JOIN ทุกประการ

## หา "แถวที่ไม่มีคู่" (anti-join)

```python
merged = customers.merge(orders, on='customer_id', how='left')
merged[merged['order_id'].isna()]
```

หลักการ: `how='left'` ทำให้แถวที่จับคู่ไม่ได้มีค่า NaN ในคอลัมน์ของตารางขวา กรองด้วย `.isna()` บนคอลัมน์คีย์
ของตารางขวาก็จะเหลือเฉพาะแถวที่ "ไม่มีคู่" จริงๆ

## เชื่อมได้มากกว่า 2 ตาราง — และปัญหาแถวเบิ้ล (fan-out)

```python
order_items.merge(orders, on='order_id').merge(products, on='product_id')
```

ต่อ `.merge()` กันได้เรื่อยๆ แต่ต้องระวัง **fan-out**: ถ้าตารางที่เชื่อมมีความสัมพันธ์แบบ "หนึ่งต่อหลาย"
(1 ออเดอร์มีหลายรายการสินค้า) การ merge จะคูณแถวขึ้นตามจำนวนรายการ ทำให้ `len(...)` นับเกินจำนวนที่ต้องการ
วิธีแก้คือใช้ `.nunique()` บนคีย์ของตารางที่ไม่อยากให้นับซ้ำ

## Self-merge

merge ตารางกับตัวเองก็ทำได้ ใช้เมื่อต้องการเทียบแถวในตารางเดียวกันเอง เช่น "หาสินค้าคู่ที่ราคาใกล้กัน"
ต้องใส่ `suffixes=(...)` กันชื่อคอลัมน์ที่ซ้ำกันชนกัน และมักต้องมีเงื่อนไข `id_1 < id_2` กันไม่ให้นับคู่ซ้ำ
