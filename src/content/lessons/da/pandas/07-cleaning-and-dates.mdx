## ข้อมูลจริงไม่เคยสะอาด

บทนี้ใช้ไฟล์ `data/raw/customers_raw.csv` — เวอร์ชัน "ดิบ" ของตาราง customers ที่มีปัญหาจริงปนอยู่:
ค่าว่างบางช่อง, แถวซ้ำ, ชื่อเมืองเขียนไม่ตรงกัน, และวันที่สมัคร (signup_date) ที่เขียนได้หลายรูปแบบปนกัน
เป้าหมายของบทนี้คือฝึกทำความสะอาดให้เหมือนของจริง

## หา missing values

```python
raw.isna().sum()
```

`.isna()` คืน True/False ทีละช่อง ต่อด้วย `.sum()` จะนับจำนวน True ในแต่ละคอลัมน์ทันที

**ระวัง:** ช่อง CSV ที่ว่างเปล่าจะถูกอ่านเป็นค่า missing (`NaN`) เสมอ **ไม่ใช่สตริงว่าง** `''`
ถ้าเขียน `raw['email'] == ''` เพื่อหาแถวที่ไม่มีอีเมล จะไม่เจอสักแถวเดียว ต้องใช้ `.isna()` เท่านั้น

จัดการค่าว่างได้สองทาง: `dropna(subset=['col'])` (ลบแถวที่คอลัมน์นั้นว่าง) หรือ `fillna(ค่า)` (เติมค่าแทนที่)

## หาและลบแถวที่ซ้ำกัน

```python
raw.duplicated().sum()      # นับจำนวนแถวที่ซ้ำ (แถวแรกของกลุ่มไม่นับ)
raw.duplicated(keep=False)  # ทำเครื่องหมายทุกแถวที่มีคู่ซ้ำ รวมแถวแรกด้วย
raw.drop_duplicates()       # ลบสำเนาส่วนเกินออก เหลือไว้แถวเดียวต่อกลุ่ม
```

## ทำความสะอาดข้อความ

ค่าที่ควรเหมือนกัน (เช่น `"Bangkok"`, `" bangkok "`, `"BANGKOK "`) มักถูกนับแยกกันเพราะช่องว่าง/ตัวพิมพ์
ไม่ตรงกัน แก้ด้วยการต่อเชนกัน:

```python
raw['city'].str.strip().str.title()
```

**ระวัง:** ต้อง `.strip()` (ตัดช่องว่างหน้า-หลัง) ก่อนเสมอ แล้วค่อยจัดการตัวพิมพ์ ถ้าทำ `.str.upper()`
อย่างเดียวโดยไม่ strip ก่อน ค่าที่มีช่องว่างเกินจะยังถูกนับแยกจากค่าที่ไม่มีช่องว่างอยู่ดี

## วันที่หลายรูปแบบปนกันในคอลัมน์เดียว

คอลัมน์ `signup_date` เขียนได้ 3 แบบปนกัน: `'2024-01-03'` (ISO), `'03/01/2024'` (DD/MM/YYYY),
`'2024/01/03'` (YYYY/MM/DD) — ตัวเลขวันเดียวกันแต่เขียนคนละแบบ

```python
pd.to_datetime(raw['signup_date'])  # ❌ error: รูปแบบไม่ตรงกันทั้งคอลัมน์
```

ลองแก้แบบง่ายๆ ก่อน:

```python
pd.to_datetime(raw['signup_date'], format='mixed')  # ✔ ไม่ error แต่...
```

ใช้ได้ไม่ error แต่ **ผลลัพธ์ผิด** สำหรับแถวแบบ DD/MM/YYYY เพราะ `format='mixed'` ให้ pandas เดารูปแบบ
เอง และค่าเริ่มต้นจะตีความ `'03/01/2024'` เป็น "เดือน 03 วัน 01" (month-first) ทั้งที่จริงคือ 3 มกราคม

ลองเติม `dayfirst=True` เพื่อบอกว่า "ให้อ่านวันก่อนเดือน":

```python
pd.to_datetime(raw['signup_date'], format='mixed', dayfirst=True)  # ❌ ยังผิด!
```

**ยืนยันแล้วว่ายังผิด** — คราวนี้กลับไปทำให้สตริงแบบ ISO ที่ไม่กำกวมอยู่แล้ว (เช่น `'2024-01-03'`)
ถูกตีความผิดไปด้วย (`dayfirst=True` มีผลกับทุกสตริงที่ parse แบบ `mixed` ไม่ใช่แค่สตริงที่กำกวมจริงๆ)
กลายเป็น `'2024-03-01'` ซึ่งผิด

### วิธีที่ถูกต้อง: parse แยกทีละรูปแบบ แล้ว combine_first

```python
d1 = pd.to_datetime(raw['signup_date'], format='%Y-%m-%d', errors='coerce')
d2 = pd.to_datetime(raw['signup_date'], format='%d/%m/%Y', errors='coerce')
d3 = pd.to_datetime(raw['signup_date'], format='%Y/%m/%d', errors='coerce')
parsed = d1.combine_first(d2).combine_first(d3)
```

หลักการ: ระบุ `format=` ที่ตรงเป๊ะทีละรูปแบบ พร้อม `errors='coerce'` (ค่าที่ไม่ตรงรูปแบบนั้นจะกลายเป็น
`NaT` แทนที่จะ error) แล้วรวมผลทั้งหมดด้วย `.combine_first()` ตามลำดับ — แต่ละขั้นจะเติมเฉพาะช่องที่
ยังเป็น `NaT` อยู่ ผลสุดท้ายควรเช็ค `.isna().sum()` ว่าเป็น 0 เพื่อยืนยันว่าแปลงครบทุกแถวจริง

## chained assignment: ไม่ error ไม่ warning แต่ก็ไม่มีผลอะไรเลย

```python
sub = df[df['a'] > 1]
sub['a'] = 99          # ⚠️ ไม่ error, ไม่ warning, แต่ df ต้นฉบับไม่เปลี่ยนแปลง
```

`df[เงื่อนไข]` อาจคืนสำเนา (copy) ของข้อมูล การเขียนต่อด้วย `['col'] = ค่า` (chained indexing) จึงอาจแก้
แค่สำเนาชั่วคราวที่ไม่มีใครอ้างอิงถึงอีกแล้ว — เวอร์ชันก่อนหน้าเคยมี `SettingWithCopyWarning` เตือน
แต่ pandas ปัจจุบัน (ที่ใช้ Copy-on-Write เป็นค่าเริ่มต้น) **ไม่แสดง warning นี้อีกต่อไป** โค้ดจึงดูเหมือน
รันผ่านปกติทุกอย่างทั้งที่ไม่ได้ผลอะไรเลย

ทางที่ปลอดภัยเสมอ:

```python
df.loc[df['a'] > 1, 'a'] = 99   # ✔ แก้ไขข้อมูลต้นฉบับจริง
```
