## ดึงข้อมูลด้วย SELECT

คำสั่งพื้นฐานที่สุดของ SQL คือบอกว่า "อยากได้คอลัมน์ไหน จากตารางไหน"

```sql
SELECT product_name, price FROM products
```

- `SELECT *` ดึงทุกคอลัมน์ — สะดวกตอนสำรวจข้อมูลครั้งแรก แต่ในงานจริงควรระบุคอลัมน์ที่ใช้จริงเพื่อให้ผลลัพธ์อ่านง่ายและ query เร็วขึ้น
- ตั้งชื่อคอลัมน์ผลลัพธ์ใหม่ได้ด้วย `AS` เช่น `SELECT COUNT(*) AS n_orders`

Dataset ของสายนี้มี 5 ตาราง: `customers`, `products`, `orders`, `order_items`, `events` (ดูรายละเอียดคอลัมน์แต่ละตารางได้จากบท "Data Analyst ทำอะไร")

## กรองแถวด้วย WHERE

`WHERE` เลือกเฉพาะแถวที่ตรงเงื่อนไข ตัวดำเนินการที่ใช้บ่อย:

| ตัวดำเนินการ | ความหมาย | ตัวอย่าง |
| --- | --- | --- |
| `=`, `<>`, `>`, `<`, `>=`, `<=` | เปรียบเทียบตรงๆ | `price > 1000` |
| `AND`, `OR` | รวมหลายเงื่อนไข | `category='Books' AND price<500` |
| `IN (...)` | ตรงกับค่าใดค่าหนึ่งในลิสต์ | `status IN ('cancelled','returned')` |
| `BETWEEN a AND b` | อยู่ในช่วง (รวมขอบทั้งสองด้าน) | `price BETWEEN 500 AND 1000` |
| `LIKE` | จับคู่รูปแบบข้อความ (`%` แทนตัวอักษรกี่ตัวก็ได้) | `email LIKE '%@example.com'` |
| `IS NULL` / `IS NOT NULL` | เช็กว่าเป็นค่าว่างไหม | `discount_pct IS NULL` |

**สิ่งที่มักพลาด:**

- การเทียบสตริงสนใจตัวพิมพ์เล็ก-ใหญ่ `'Books'` กับ `'books'` ถือว่าต่างกัน
- `AND` ทำงานก่อน `OR` เสมอ (เหมือน `×` ทำก่อน `+` ในเลขคณิต) ถ้าผสมกันควรใส่วงเล็บให้ชัดเจนว่าต้องการอะไร
- `= NULL` ไม่มีทางเป็นจริง เพราะ NULL แปลว่า "ไม่รู้ค่า" ต้องใช้ `IS NULL` แทน

## เรียงและตัดผลลัพธ์ด้วย ORDER BY และ LIMIT

```sql
SELECT product_name, price FROM products
ORDER BY price DESC
LIMIT 5
```

- ค่าเริ่มต้นของ `ORDER BY` คือ `ASC` (น้อยไปมาก) ใส่ `DESC` เพื่อเรียงมากไปน้อย
- เรียงได้หลายคอลัมน์: `ORDER BY a, b` เรียงตาม `a` ก่อน ถ้า `a` เท่ากันจึงค่อยดู `b` เป็นตัวตัดสิน (tie-break)
- `LIMIT n` ตัดผลลัพธ์เหลือ `n` แถวแรกตามลำดับที่เรียงไว้ — **ถ้าไม่มี ORDER BY ก่อน LIMIT ผลลัพธ์จะไม่แน่นอนว่าได้แถวไหนบ้าง**
- เวลาต้องการ "N อันดับแรก" แบบเป๊ะๆ (เช่นในแบบฝึกที่ต้องตรวจคำตอบอัตโนมัติ) ควรมีคอลัมน์ตัดสินเสมอเมื่อค่าที่เรียงอาจซ้ำกันได้ ไม่งั้นจะได้คนละแถวกันในแต่ละครั้งที่รัน
