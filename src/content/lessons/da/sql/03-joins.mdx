## ทำไมต้อง JOIN

ข้อมูลของร้านค้าออนไลน์กระจายอยู่หลายตาราง — ลูกค้าอยู่ที่ `customers` ออเดอร์อยู่ที่ `orders`
รายการสินค้าในแต่ละออเดอร์อยู่ที่ `order_items` และรายละเอียดสินค้าอยู่ที่ `products`
`JOIN` คือการเชื่อมตารางเหล่านี้เข้าด้วยกันตาม "คีย์" ที่เชื่อมโยงกัน

```sql
SELECT o.order_id, c.city
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
```

## INNER JOIN vs LEFT JOIN vs RIGHT JOIN vs FULL JOIN

| แบบ | เก็บแถวไหนไว้ |
| --- | --- |
| `INNER JOIN` (หรือเขียนแค่ `JOIN`) | เฉพาะแถวที่จับคู่ได้ทั้งสองฝั่ง |
| `LEFT JOIN` | ทุกแถวจากตารางซ้าย ต่อให้หาคู่ในตารางขวาไม่เจอก็ใส่ NULL แทน |
| `RIGHT JOIN` | ทุกแถวจากตารางขวา (ตรงข้ามกับ LEFT) |
| `FULL JOIN` | ทุกแถวจากทั้งสองฝั่ง ไม่ว่าจะจับคู่ได้หรือไม่ |

ลองเชื่อม `customers` กับ `orders` ทั้ง 4 แบบดู แล้วสังเกตจำนวนแถวที่ได้:

| แบบ | จำนวนแถว |
| --- | --- |
| INNER | 6,938 |
| LEFT | 7,399 |
| RIGHT | 6,938 |
| FULL | 7,399 |

สังเกตว่า **RIGHT เท่ากับ INNER** และ **FULL เท่ากับ LEFT** ในกรณีนี้ — เพราะทุกออเดอร์อ้างอิงลูกค้าที่มีจริงเสมอ
(ไม่มี "ออเดอร์กำพร้า") ความต่างระหว่าง RIGHT/FULL กับ INNER/LEFT จะเห็นชัดก็ต่อเมื่อฝั่งขวา (หรือทั้งสองฝั่ง)
มีแถวที่จับคู่ไม่ได้ ซึ่งในที่นี้เกิดฝั่ง `customers` แทน — มีลูกค้า 461 คนที่ไม่เคยมีออเดอร์เลย ทำให้ LEFT JOIN
ได้แถวเพิ่มมา 461 แถว (7,399 − 6,938) นี่คือสิ่งที่ LEFT JOIN เผยให้เห็น

## หา "แถวที่ไม่มีคู่" (anti-join)

รูปแบบที่ใช้บ่อยมากคือหา "อะไรที่ไม่มี" เช่น ลูกค้าที่ไม่เคยสั่งซื้อ:

```sql
SELECT c.customer_id FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id
WHERE o.order_id IS NULL
```

หลักการ: LEFT JOIN ทำให้แถวที่จับคู่ไม่ได้มีค่า NULL ในคอลัมน์ของตารางขวา กรองด้วย `IS NULL`
บนคอลัมน์คีย์ของตารางขวา ก็จะเหลือเฉพาะแถวที่ "ไม่มีคู่" จริงๆ

## เชื่อมได้มากกว่า 2 ตาราง — และปัญหาแถวเบิ้ล (fan-out)

```sql
SELECT p.category, SUM(i.quantity * i.unit_price) AS revenue
FROM orders o
JOIN order_items i ON o.order_id = i.order_id
JOIN products p ON i.product_id = p.product_id
GROUP BY p.category
```

เชื่อมกี่ตารางก็ได้ต่อกันเรื่อยๆ แต่ต้องระวัง **fan-out**: ถ้าตารางที่เชื่อมมีความสัมพันธ์แบบ
"หนึ่งต่อหลาย" (1 ออเดอร์มีหลายรายการสินค้า) การ JOIN จะคูณแถวขึ้นตามจำนวนรายการ ทำให้ `COUNT(*)`
นับเกินจำนวนที่ต้องการ (เช่น นับ "รายการสินค้า" ทั้งที่ตั้งใจนับ "ออเดอร์") วิธีแก้คือใช้ `COUNT(DISTINCT ...)`
บนคีย์ของตารางที่ไม่อยากให้นับซ้ำ

## USING เมื่อชื่อคอลัมน์ตรงกัน

ถ้าคอลัมน์ที่ใช้เชื่อมชื่อเดียวกันทั้งสองตาราง เขียนสั้นลงได้ด้วย `USING`:

```sql
SELECT * FROM order_items i JOIN products p USING(product_id)
-- เท่ากับ: JOIN products p ON i.product_id = p.product_id
```

## Self-join

JOIN ตารางกับตัวเองก็ทำได้ ใช้เมื่อต้องการเทียบแถวในตารางเดียวกันเอง เช่น "หาสินค้าคู่ที่ราคาใกล้กัน"
ต้องตั้งชื่อ alias ให้ต่างกัน (เช่น `p1`, `p2`) และมักต้องมีเงื่อนไข `p1.id < p2.id` กันไม่ให้นับคู่ซ้ำ
