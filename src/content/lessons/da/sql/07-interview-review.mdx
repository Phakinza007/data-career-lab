## ทบทวนก่อนเข้าห้องสัมภาษณ์

บทนี้ไม่มีเนื้อหาใหม่ แต่รวมเทคนิคจาก 6 บทที่ผ่านมาเข้าด้วยกันในรูปแบบที่คำถามสัมภาษณ์จริงมักถาม:
คำถามที่ดูตรงไปตรงมาแต่ซ่อนกับดักไว้ และคำถามที่ต้องใช้หลายเทคนิคผสมกัน

## รูปแบบ "อันดับที่ N" — คำถามคลาสสิกที่พบบ่อยมาก

คำถามแบบ "หาเงินเดือนสูงสุดอันดับ 2" หรือ "สินค้าราคาถูกอันดับ 3" เป็นคำถามที่พบได้บ่อยมากในห้องสัมภาษณ์
บางบริษัทจะขอให้ทำโดย**ไม่ใช้ LIMIT/OFFSET** เพื่อทดสอบว่าเข้าใจแนวคิดการจัดอันดับข้อมูลจริงๆ

มี 2 วิธีหลัก:

1. **Subquery เทียบค่า:** หาค่าที่ "มากที่สุดที่ยังน้อยกว่าค่าสูงสุด" — ใช้ได้ดีเมื่อต้องการแค่ค่าเดียว ไม่ต้องมีคอลัมน์อื่นประกอบ
2. **DENSE_RANK แล้วกรอง:** ยืดหยุ่นกว่า ยังคืนคอลัมน์อื่นๆ มาด้วยได้ และสำคัญที่สุดคือ **ทำงานถูกต้องแม้มีค่าซ้ำกันที่อันดับสูงกว่า**

**จุดที่มักพลาด:** ใช้ `RANK` แทน `DENSE_RANK` — ถ้าอันดับ 1 มีค่าซ้ำกัน 2 แถว `RANK` จะข้ามอันดับ 2 ไปเลย
(กลายเป็น 1, 1, 3) ทำให้กรอง `WHERE rnk = 2` แล้วไม่เจอผลลัพธ์ใดๆ ทั้งที่ควรมีคำตอบ

## รวมหลายเทคนิคเข้าด้วยกัน

โจทย์ธุรกิจในงานจริง (และในห้องสัมภาษณ์ระดับที่สูงขึ้น) มักไม่ได้ใช้แค่เทคนิคเดียว เช่น:

- "ลูกค้าที่ซื้อซ้ำแต่ไม่เคยยกเลิกเลย" → GROUP BY/HAVING (หา "ซื้อซ้ำ") + NOT EXISTS (กรอง "ไม่เคยยกเลิก")
- "session ที่ผ่านครบทุกขั้นของ funnel" → COUNT DISTINCT + subquery ห่อกรองค่า
- "หมวดที่มีสัดส่วนรายได้เกิน 10%" → CTE คำนวณยอดรวมจริงแยกไว้ก่อน + window function

เวลาเจอโจทย์ที่ซับซ้อน ให้แตกออกเป็นขั้นย่อยๆ ก่อน (มักทำเป็น CTE ทีละขั้น) แล้วค่อยประกอบกัน
ไม่ต้องพยายามเขียนให้จบในคำสั่งเดียวตั้งแต่แรก

## กับดักที่ต้องระวังเป็นพิเศษ: WHERE กับ window function

ถ้าใช้ `SUM(...) OVER ()` (ไม่มี PARTITION BY) เพื่อหา "สัดส่วนต่อยอดรวม" แต่คำนวณมันในจุดที่ query
มี `WHERE` กรองแถวออกไปก่อนแล้ว window function จะเห็นแค่แถวที่เหลือหลังกรอง ไม่ใช่ข้อมูลทั้งหมดตั้งแต่ต้น
ทำให้ "สัดส่วน" ที่ได้คลาดเคลื่อนไปจากความเป็นจริง

ถ้าต้องการฐานคำนวณจากข้อมูลทั้งหมด (ก่อนกรอง) ต้องแยกคำนวณยอดรวมไว้ต่างหากใน CTE ก่อน
แล้วค่อยเอามาประกอบกับข้อมูลที่กรองแล้วทีหลัง (ดูตัวอย่างในแบบฝึก `e9`)

## เตรียมตัวสำหรับคำถามที่ไม่ใช่โค้ด

ห้องสัมภาษณ์ SQL มักมีคำถามเชิงแนวคิดปนมาด้วย เช่น "อธิบายลำดับการทำงานของ query" หรือ
"เจอผลลัพธ์ที่ดูเยอะเกินจริงหลัง JOIN ควรตรวจอะไรก่อน" — คำถามเหล่านี้วัดว่าเข้าใจ SQL จริงๆ
ไม่ใช่แค่จำ syntax ได้ ทบทวนหัวข้อ "คำถามสัมภาษณ์" ท้ายทุกบทของโมดูลนี้ให้คล่องก่อนเข้าสัมภาษณ์จริง
