## ทำไมต้องมี "การทดสอบสมมติฐาน"

บทที่แล้วเราเรียนรู้ว่าค่าเฉลี่ยจากตัวอย่างมีความไม่แน่นอน จึงต้องรายงานเป็นช่วง (confidence interval) แทนที่จะเป็นตัวเลขเดียว
คำถามต่อไปที่พบบ่อยในงานวิเคราะห์คือ: "มีคนอ้างตัวเลขบางอย่างมา (เช่น ยอดขายเฉลี่ยคือ X บาท) ข้อมูลตัวอย่างที่เรามีขัดแย้ง
กับคำกล่าวนั้นไหม" หรือ "สองกลุ่มนี้ค่าเฉลี่ยต่างกันจริงหรือแค่ต่างกันเพราะสุ่มตัวอย่างมาไม่เหมือนกัน" — **การทดสอบสมมติฐาน
(hypothesis testing)** คือกรอบการคิดที่ตอบคำถามแบบนี้อย่างเป็นระบบ

### null hypothesis (H0) กับ alternative hypothesis (H1)

ทุกการทดสอบสมมติฐานเริ่มจากตั้งสมมติฐานคู่หนึ่ง:

- **H0 (null hypothesis)** — สมมติฐานที่บอกว่า "ไม่มีความแตกต่าง / ไม่มีผล" เช่น "ยอดขายเฉลี่ย = 5000 บาท" หรือ "ค่าเฉลี่ย
  ของสองกลุ่มเท่ากัน" นี่คือสิ่งที่เรา**พยายามหาหลักฐานมาหักล้าง** ไม่ใช่สิ่งที่เราอยากพิสูจน์
- **H1 (alternative hypothesis)** — สมมติฐานตรงข้าม เช่น "ยอดขายเฉลี่ย ≠ 5000 บาท" หรือ "ค่าเฉลี่ยของสองกลุ่มไม่เท่ากัน"

ตรรกะสำคัญคือ: เราไม่มีทาง "พิสูจน์" ว่า H0 เป็นจริงได้ 100% ทำได้แค่ดูว่าข้อมูลที่มี**มีหลักฐานเพียงพอที่จะปฏิเสธ H0** หรือไม่
ถ้าไม่มีหลักฐานเพียงพอ เราจะพูดว่า **"fail to reject H0"** (ไม่ปฏิเสธ H0) ไม่ใช่ "H0 เป็นจริงแน่นอน"

## One-sample t-test — เทียบค่าเฉลี่ยตัวอย่างกับค่าที่มีคนอ้าง

สมมติผู้บริหารอ้างว่า **ยอดออเดอร์เฉลี่ยของร้านคือ 5000 บาท** ทีมอยากตรวจสอบด้วยตัวอย่าง 200 ออเดอร์ — ใช้ตัวอย่างชุด
เดียวกับบทที่แล้วเป๊ะๆ (`seed=42`, `size=200`, `replace=False` จากยอดขายต่อออเดอร์ที่เสร็จสมบูรณ์) เพื่อให้ผลลัพธ์ตรงกันทุกครั้ง:

```python
import pandas as pd
import numpy as np
from scipy import stats

orders = pd.read_csv("data/orders.csv")
order_items = pd.read_csv("data/order_items.csv")

merged = order_items.merge(orders, on='order_id')
completed = merged[merged['status'] == 'completed'].copy()
completed['line'] = completed['quantity'] * completed['unit_price']
order_rev = completed.groupby('order_id')['line'].sum()

rng = np.random.default_rng(42)
sample = rng.choice(order_rev.values, size=200, replace=False)

t_stat, p_value = stats.ttest_1samp(sample, 5000)
```

ในที่นี้ H0 คือ "ค่าเฉลี่ยจริง = 5000" ส่วน H1 คือ "ค่าเฉลี่ยจริง ≠ 5000" — ผลที่ได้: `t_stat ≈ 1.908`, `p_value ≈ 0.0578`

ที่ระดับนัยสำคัญ (significance level) มาตรฐาน `α = 0.05`: เพราะ `p_value (0.0578) > α (0.05)` เราจึง **fail to reject H0** —
ข้อมูลตัวอย่างนี้ไม่ได้ขัดแย้งกับคำกล่าวที่ว่ายอดเฉลี่ยคือ 5000 บาทอย่างมีนัยสำคัญ

## p-value คืออะไรกันแน่ (และไม่ใช่อะไร)

**p-value คือ: ถ้า H0 เป็นจริงจริงๆ โอกาสที่จะสุ่มตัวอย่างมาแล้วได้ผลลัพธ์สุดขั้วเท่านี้หรือมากกว่านี้ คือเท่าไหร่**

ในตัวอย่างข้างบน `p_value ≈ 0.0578` แปลว่า "ถ้ายอดเฉลี่ยจริงเท่ากับ 5000 บาทจริงๆ โอกาสที่จะสุ่มตัวอย่าง 200 ออเดอร์มาแล้ว
ได้ค่าเฉลี่ยที่ต่างจาก 5000 มากเท่ากับที่เราเห็น (หรือมากกว่า) คือ 5.78%"

> **ข้อควรระวังที่พบบ่อยที่สุด:** อย่าอ่าน `p_value = 0.0578` ว่า "มีโอกาส 94.2% ที่คำกล่าวของผู้บริหารเป็นจริง" — p-value
> **ไม่ใช่** ความน่าจะเป็นที่ H0 เป็นจริง มันคือความน่าจะเป็นของข้อมูล **ภายใต้สมมติฐานว่า H0 เป็นจริง** ต่างหาก คนละคำถามกัน

สรุปการอ่านผลให้ถูก:

| ผลลัพธ์ | อ่านว่าอะไร | อ่านผิดที่พบบ่อย |
| --- | --- | --- |
| `p < 0.05` (ปฏิเสธ H0) | มีหลักฐานเพียงพอที่จะบอกว่าข้อมูลขัดแย้งกับ H0 อย่างมีนัยสำคัญ | "พิสูจน์แล้วว่า H1 เป็นจริง 100%" |
| `p ≥ 0.05` (fail to reject) | ข้อมูลที่มีไม่พอจะหักล้าง H0 ได้ | "พิสูจน์แล้วว่า H0 เป็นจริง 100%" |

## Two-sample t-test — เทียบค่าเฉลี่ยระหว่างสองกลุ่ม

อีกคำถามที่พบบ่อยกว่าคือเทียบค่าเฉลี่ยของ **สองกลุ่ม** เช่น "ลูกค้าที่มาจากช่องทาง organic กับ ads ใครสั่งซื้อเฉลี่ยต่อ
ออเดอร์สูงกว่ากัน" ที่นี่ H0 คือ "ค่าเฉลี่ยของสองกลุ่มเท่ากัน"

```python
import pandas as pd
from scipy import stats

orders = pd.read_csv("data/orders.csv")
order_items = pd.read_csv("data/order_items.csv")
customers = pd.read_csv("data/customers.csv")

completed = orders[orders['status'] == 'completed']
oc = completed.merge(customers[['customer_id', 'channel']], on='customer_id')
items = order_items.merge(oc[['order_id', 'channel']], on='order_id')
items['line'] = items['quantity'] * items['unit_price']
rev_by_order = items.groupby(['order_id', 'channel'])['line'].sum().reset_index()

organic = rev_by_order[rev_by_order['channel'] == 'organic']['line']   # n=3010, mean≈5405.2
ads = rev_by_order[rev_by_order['channel'] == 'ads']['line']           # n=2034, mean≈5015.77

t2, p2 = stats.ttest_ind(organic, ads, equal_var=False)
```

ผลที่ได้: `t2 ≈ 1.8537`, `p2 ≈ 0.0639` — เพราะ `p2 > 0.05` จึง fail to reject H0 เช่นกัน: **ไม่มีหลักฐานเพียงพอที่จะบอกว่า
สองช่องทางนี้มียอดสั่งซื้อเฉลี่ยต่างกันอย่างมีนัยสำคัญ** แม้ตัวเลขดิบ (5405.2 vs 5015.77) จะดูต่างกันพอสมควรก็ตาม — นี่คือ
เหตุผลที่ต้องทดสอบทางสถิติ ไม่ใช่ดูตัวเลขดิบแล้วสรุปเอง เพราะความต่างขนาดนี้อาจเกิดจากการสุ่มตัวอย่างมาไม่เท่ากันล้วนๆ ก็ได้

### ทำไมต้องใช้ `equal_var=False` (Welch's t-test)

`scipy.stats.ttest_ind` มีสองโหมด:

- `equal_var=True` (ค่าเริ่มต้น) — **Student's t-test** ดั้งเดิม สมมติว่าความแปรปรวนของสองกลุ่ม**เท่ากัน**
- `equal_var=False` — **Welch's t-test** ไม่สมมติว่าความแปรปรวนเท่ากัน

ในทางปฏิบัติ เรามักไม่รู้ล่วงหน้าว่าความแปรปรวนของสองกลุ่มเท่ากันจริงไหม (และข้อมูลยอดขาย/รายได้มักมีความแปรปรวนต่างกัน
ระหว่างกลุ่มด้วย) จึงแนะนำให้ใช้ `equal_var=False` เป็นค่าเริ่มต้นเสมอเมื่อไม่แน่ใจ — ปลอดภัยกว่าและแทบไม่มีข้อเสีย

## ทำไม α ที่เลือกไว้ล่วงหน้าถึงสำคัญ

`α = 0.05` เป็นธรรมเนียมที่ใช้กันแพร่หลาย แต่ไม่ใช่กฎเหล็กทางคณิตศาสตร์ — ถ้าทีมเลือกใช้ `α = 0.10` แทน ผลการทดสอบ
two-sample t-test ข้างบน (`p2 ≈ 0.0639`) จะกลายเป็น "มีนัยสำคัญ" ทันที (`0.0639 < 0.10`) ทั้งที่ข้อมูลไม่ได้เปลี่ยนเลย
สักตัวเลขเดียว — นี่คือเหตุผลว่าทำไมควร**กำหนด α ไว้ล่วงหน้าก่อนดูผล** ไม่ใช่เลือก α ทีหลังเพื่อให้ได้ข้อสรุปที่อยากได้
(รูปแบบหนึ่งของ p-hacking) และทำไมผลลัพธ์ที่ p-value อยู่ใกล้เส้นแบ่ง (เช่น 0.049 vs 0.051) ไม่ควรถูกตีความว่าต่างกัน
อย่างมีนัยสำคัญในทางปฏิบัติ
