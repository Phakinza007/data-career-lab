## Dashboard ที่ดีตอบคำถามได้ในสายตาเดียว

บทที่แล้วเรียนวิธีวาดกราฟทีละใบด้วย matplotlib/seaborn ในบทนี้จะพูดถึงการเอากราฟหลายใบมา
"จัดวาง" รวมกันเป็น **dashboard** — สิ่งที่ผู้บริหารหรือทีมธุรกิจเปิดดูทุกวัน

หลักการข้อแรกและสำคัญที่สุด: dashboard ที่ดีต้องตอบ**คำถามหลัก**ได้ทันทีที่เปิดขึ้นมา
โดยไม่ต้อง scroll ลงไปหา ไม่ต้องคลิกกรองเพิ่ม ไม่ต้อง zoom เข้าไปอ่านตัวเลข — ถ้าผู้บริหารต้อง
ถามกลับว่า "ตอนนี้ยอดขายดีขึ้นหรือแย่ลง" แปลว่า dashboard นั้นยังทำหน้าที่ไม่สำเร็จ

## โครงสร้างที่ใช้บ่อย: KPI card + เทรนด์ + breakdown

dashboard ส่วนใหญ่ในงานจริง (ยอดขาย, การตลาด, product) ใช้โครงสร้างเดียวกันซ้ำๆ อยู่ 3 ส่วน:

| ส่วน | ตอบคำถามว่า | ตัวอย่าง |
| --- | --- | --- |
| **KPI card** | ตอนนี้เป็นยังไง เทียบกับก่อนหน้าเปลี่ยนไปแค่ไหน | "รายได้ พ.ย. 2025: 2,059,592 บาท (+60.73% เทียบเดือนก่อน)" |
| **เทรนด์ (trend)** | แนวโน้มตามเวลาเป็นยังไง กำลังขึ้นหรือลง | กราฟเส้นรายได้รายเดือน |
| **breakdown** | ตัวเลขรวมมาจากไหนบ้าง ส่วนไหนมีสัดส่วนเยอะ | กราฟแท่งรายได้แยกตามหมวดสินค้า |

ตัวอย่าง KPI card แบบง่ายที่สุดคือการเทียบเดือนนี้กับเดือนก่อนหน้า (month-over-month, MoM):

```python
import pandas as pd

orders = pd.read_csv("data/orders.csv")
order_items = pd.read_csv("data/order_items.csv")

completed = orders[orders['status'] == 'completed'].copy()
order_items = order_items.copy()
order_items['line'] = order_items['quantity'] * order_items['unit_price']
merged = order_items.merge(completed[['order_id', 'order_date']], on='order_id')
merged['month'] = merged['order_date'].str[:7]
monthly = merged[merged['month'].str.startswith('2025')].groupby('month')['line'].sum()

nov_revenue = monthly['2025-11']
oct_revenue = monthly['2025-10']
mom_pct = round((nov_revenue - oct_revenue) / oct_revenue * 100, 2)
```

ตัวเลข `mom_pct` ที่ได้ (`+60.73`) คือสิ่งที่ KPI card ควรโชว์ **คู่กับ** ตัวเลขดิบ (`2,059,592`) เสมอ —
ตัวเลขดิบเพียงอย่างเดียวไม่บอกว่าดีขึ้นหรือแย่ลง ส่วน % เปลี่ยนแปลงเพียงอย่างเดียวก็ไม่บอกขนาดจริง
ของธุรกิจ ต้องมีทั้งคู่ และ dashboard จริงมักใส่สีเขียว/แดงกับลูกศรขึ้น/ลงกำกับ % นั้นด้วย เพื่อให้
สายตากวาดผ่านแล้ว "รู้ทันที" โดยไม่ต้องอ่านตัวเลข

เทรนด์กับ breakdown มักวางคู่กันในหน้าเดียว เพราะตอบคำถามคนละมุมของเรื่องเดียวกัน — เทรนด์บอกว่า
"ภาพรวมกำลังไปทางไหน" ส่วน breakdown บอกว่า "ที่เห็นนั้นมาจากส่วนไหนบ้าง"

## ความสม่ำเสมอทั่วทั้ง dashboard

เมื่อมีกราฟหลายใบอยู่ในหน้าเดียวกัน รายละเอียดเล็กๆ ที่ไม่สม่ำเสมอจะกลายเป็นภาระของผู้อ่านทันที:

- **สี** — ถ้าสีแดงหมายถึง "ลดลง" ในกราฟหนึ่ง แต่หมายถึงหมวดสินค้าหนึ่งในอีกกราฟ คนอ่านจะเข้าใจผิด
  ควรกำหนดความหมายของสีให้ตรงกันทั้ง dashboard (เช่น เขียว = ดีขึ้น/บวกเสมอ, แดง = แย่ลง/ลบเสมอ)
- **หน่วย** — ถ้ากราฟหนึ่งโชว์รายได้เป็นบาท อีกกราฟโชว์เป็นพันบาท (K) โดยไม่บอกไว้ชัดๆ คนอ่านจะเทียบตัวเลข
  ข้ามกราฟผิดได้ง่าย
- **การปัดเศษ** — ถ้า KPI card หนึ่งปัด 0 ตำแหน่ง อีกอันปัด 2 ตำแหน่ง ตัวเลขจะดูไม่เป็นระบบเดียวกัน

ความสม่ำเสมอพวกนี้ไม่ใช่เรื่องความสวยงามอย่างเดียว แต่ลดภาระการตีความของผู้อ่านโดยตรง — ยิ่งต้องคิดน้อย
ก็ยิ่งอ่านเร็วและตัดสินใจได้เร็ว ซึ่งเป็นเป้าหมายหลักของ dashboard ตั้งแต่แรก

## เครื่องมือในงานจริง เทียบกับสิ่งที่เรียนในเว็บนี้

ในงานจริง DA ส่วนใหญ่ไม่ได้สร้าง dashboard ด้วย matplotlib/seaborn ใน notebook แต่ใช้เครื่องมือ
แบบ drag-and-drop ที่เชื่อมต่อกับฐานข้อมูลได้โดยตรงและรีเฟรชอัตโนมัติ ที่พบบ่อยที่สุดคือ **Power BI**,
**Tableau**, และ **Looker Studio**

ข่าวดีคือแนวคิดเบื้องหลังเหมือนกันทุกประการกับที่เรียนมาทั้งบท — เลือกกราฟให้ตรงคำถาม (บทที่ 1),
เตรียมข้อมูลให้พร้อม (groupby/aggregate แบบที่ทำมาตลอด), จัดเป็น KPI card + เทรนด์ + breakdown,
รักษาความสม่ำเสมอ สิ่งที่ต่างกันมีแค่ **เครื่องมือ**: เครื่องมือ drag-and-drop ทำให้สร้างกราฟเร็วขึ้นและ
เชื่อมข้อมูลสดได้ง่ายขึ้น แต่การตัดสินใจว่า "จะโชว์อะไร" และ "ทำไมถึงเลือกกราฟแบบนี้" ยังเป็นทักษะเดียวกับ
ที่ฝึกมาด้วย pandas/matplotlib ทุกอย่าง — เขียนโค้ดได้คล่องเท่ากับลาก-วางได้คล่อง เพราะพื้นฐานความคิด
เหมือนกัน
