## โจทย์ของ ML capstone

ใช้ตาราง `ml_customers` (ลูกค้า 2,839 คน; 1 แถวต่อลูกค้า) ทำนายว่าลูกค้า **จะซื้อซ้ำหรือไม่** (`repeated`) โดยใช้ข้อมูลของการสั่งซื้อครั้งแรกและช่องทางที่สมัคร
(ทางเลือกที่ยากกว่า: ทำนายมูลค่าคำสั่งซื้อแรก `first_order_value` แบบ regression)

เป้าหมายไม่ใช่ตัวเลขที่สูงที่สุด แต่คือ **กระบวนการที่เชื่อถือได้** และการสื่อสารผลตามจริง — สิ่งที่คนสัมภาษณ์มองหา

## ลำดับงานที่คาดหวัง

1. **เข้าใจโจทย์และ baseline**: อัตราซื้อซ้ำเท่าไร โมเดล "เดาคนส่วนใหญ่" ได้ accuracy เท่าไร (≈ 0.59) — ทุกโมเดลต้องเอาชนะตัวนี้
2. **แบ่งข้อมูลและกัน test ไว้ก่อน** (`train_test_split`, `stratify=y`, `random_state`) แล้วแตะ test แค่ครั้งเดียวตอนท้าย
3. **เตรียมข้อมูลใน Pipeline** (`ColumnTransformer`: scale ตัวเลข, one-hot ตัวหมวด) — ตรวจว่า feature ทุกตัวรู้ได้ ณ เวลาที่ต้องทำนาย (ไม่มี leakage)
4. **เทียบอย่างน้อย 3 โมเดล** ด้วย `StratifiedKFold(shuffle=True)`: logistic regression, ต้นไม้/forest/gradient boosting, และ (ถ้าอยากลอง) MLP รายงาน mean ± std ของ AUC และ accuracy เทียบ baseline
5. **จูนเล็กน้อย** ด้วย `GridSearchCV` บน train เท่านั้น
6. **อธิบาย**: permutation importance บน test และ/หรือ coefficient — feature ไหนที่โมเดลพึ่ง
7. **ทดสอบครั้งสุดท้าย** บน test แล้ว **สรุปตามจริง** พร้อมข้อจำกัด

## สิ่งที่ควรคาดหวังจากข้อมูลนี้ (ตามที่เราเห็นในบทก่อนๆ)

- สัญญาณที่แรงมีอย่างเดียว คือช่องทาง `promo` (ลูกค้าจาก promo ซื้อซ้ำน้อยกว่า)
- logistic regression, ต้นไม้ตื้น, forest และ boosting ได้ AUC ราว 0.62–0.66 และ accuracy 0.64–0.66 (MLP มักแย่กว่า) (baseline ≈ 0.59) — ต่างกันไม่กี่ร้อยส่วน
- ตัวเลขที่ได้ "ปานกลาง" เป็นเรื่องปกติของข้อมูลจริงที่สัญญาณอ่อน: **การรายงานตรงๆ ว่าโมเดลดีกว่า baseline แค่ไหน และไม่ควรเชื่อถือเกินกว่านั้น** สำคัญกว่าตัวเลขสวย

## Rubric ตรวจงานตัวเอง

- [ ] มี baseline และผลโมเดลทุกตัวถูกเทียบกับ baseline
- [ ] แบ่ง train/test ก่อนทำอะไรอื่น; test ถูกใช้ครั้งเดียวตอนท้าย
- [ ] การเตรียมข้อมูลอยู่ใน Pipeline (fit บน train เท่านั้น) และไม่มี feature ที่รั่วข้อมูลจากอนาคต
- [ ] เลือกโมเดล/hyperparameter ด้วย cross-validation ที่ shuffle แล้ว (รายงาน mean ± std)
- [ ] metric เหมาะกับโจทย์ (AUC + accuracy) และอธิบายว่าตัวเลขหมายถึงอะไรทางธุรกิจ
- [ ] มีส่วน "ข้อจำกัด" (ข้อมูลน้อย สัญญาณอ่อน ผลขึ้นกับ seed ฯลฯ) และ "ทำอะไรต่อ"
- [ ] notebook รันได้ทั้งไฟล์จากบนลงล่างโดยไม่ error
